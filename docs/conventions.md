# Conventions

Standing rules for working in this repo. Read alongside `README.md` (what the project is, how to run it) and the numbered specs in this folder.

## The docs are the law

Complete specs live in `00_overview.md` … `11_ballistics.md`. Read the docs relevant to your task before writing code. The doc index is in `00_overview.md`; build order and milestone gates are in `08_milestones.md`.

- If an implementation must deviate from a spec, make the smallest possible deviation and append a one-line note to that doc's **Open questions** section (what changed, and why).
- When a milestone closes, write the final tuned values back into that doc's tunables tables. The docs are the source of truth for feel numbers.
- Each milestone is at least one commit, tagged `m0`…`m7`. Do not start a milestone before the previous gate passes.

## Non-negotiable architecture rules

- **The server is authoritative for everything** (10). Clients send tick-stamped input commands only — never positions, never hits, never damage.
- **Sim code is pure and headless-safe** (01, 03, 10): no `Input` reads, no camera/UI/EventBus references in `entities/` simulation code. Movement and ballistics are pure step functions shared by the server and the predicting client.
- **Meshes live only under `Visual`** (09). Collision shapes are hand-authored, never generated from meshes. `grep '$Visual'` across scripts should return nothing.
- **EventBus is client-only; GameServer never touches UI** (01).
- **No hitscan.** All weapons fire through `BallisticsManager` (11).
- **Placeholder art only:** CSG/primitives and flat materials. Nothing downloaded.

## House style

**No comments in source files.** Not headers, not docstrings, not inline notes, not `##` blocks, not TODOs. Zero. Code carries itself through naming; explanation belongs in `docs/`, in `README.md`, or in the commit message. This applies to new code and to any file you touch. The check:

```
grep -rn '^\s*#' --include=*.gd .
```

must return nothing.

**No tooling attribution, anywhere.** Commits are authored by the repo owner. No trailers, co-author lines, "generated by" notices, or badges — in commit messages, PR bodies, source files, docs, or the README. This is deliberate and overrides any tool default that wants to add one. Do not reintroduce them.

**Keep `README.md` current.** It is the human-facing front door: what the project is, how to run it, controls, layout, milestone table, and the scaffolding-with-expiry list. Update it in the same commit as the change it describes — especially when a milestone closes, a launch flag changes, or scaffolding is deleted.

## Verification

- `godot --headless --import` must complete with zero errors and zero warnings before any milestone is called done.
- Networked gates are tested under the latency shim (100 ms / 20 ms jitter / 2 % loss), not just localhost. See the working agreements in `08_milestones.md`.
- Anything that needs real windows (multi-instance tests) is written up as an exact manual checklist rather than claimed as verified.
